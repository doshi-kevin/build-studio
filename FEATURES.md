# Scholera Features, Plainly Explained

This is a product-level tour of what Scholera does today, written for someone who isn't reading code. For the AI assistant's capabilities specifically, see [ATHENA.md](./ATHENA.md). For how the system remembers and learns from a course over time, see [MEMORY-LAYER.md](./MEMORY-LAYER.md). For what's changed recently, see [RECENT-CHANGES.md](./RECENT-CHANGES.md).

Scholera is a learning management system (the software a university runs a course through) built to replace Canvas. Every feature below sits inside an **institution** (a school), which contains **course sections** (one professor teaching one course in one semester). Almost everything a professor or student does happens inside a section.

## Who uses it

- **Students** — take the course: watch lectures, do assignments and quizzes, ask the AI tutor questions, see what's due.
- **Professors** — run the course: build content, run live classes, grade, see how the class is doing.
- **Course assistants (TAs/graders)** — use the same screens as a professor, with narrower permissions. A professor requests them; a school admin approves.
- **Institution admins** — the school's own staff. They set up departments, courses, and people, and can see everything inside their school.
- **Super admins** — Scholera's own staff. They can see across every school on the platform, mainly for billing and support.

## Course content

**Modules** are the folders a professor organizes a course into — lecture 1, lecture 2, and so on. Each module holds **items**: a lecture file, a video, a reading, a link to an assignment. A module can be "published but not open yet" (students see it's coming but can't open it), which is how a professor stages a whole semester in advance without giving it all away at once.

When a professor uploads a lecture file (a PDF, a slide deck, a Word doc), Scholera reads it in the background and turns it into structured content: the actual text on each page, any images, tables, and formulas, and a list of the concepts the material covers. This is the single most important pipeline in the product, because everything downstream — quiz questions, the AI tutor's answers, the skill map, page citations — is built from this one extraction. See [MEMORY-LAYER.md](./MEMORY-LAYER.md) for how it works.

## Quizzes

Professors build quizzes from a **question bank** — a pool of questions that live at the course level and get assigned into individual quizzes. The quiz editor is a single screen: a rail of questions, the question you're editing, and a settings panel, with a live student-view preview. Questions can be generated by AI directly from the uploaded lecture materials, each one citing exactly which page it came from.

When a student takes a quiz, grading happens on the server (so a student can't see or tamper with the answer key), answers autosave as they go, and the professor can configure negative marking, bonus/extra-credit questions, and an attached formula sheet. Results include a leaderboard.

There's also an **adaptive quiz mode**: instead of a fixed question list, the system picks one question at a time based on how the student is doing, using a standard psychometric model (the same math the GRE and other adaptive tests use) rather than guesswork. Free-response answers in this mode are graded by AI against a rubric.

Quizzes can also be **proctored**: the system can watch for tab-switching, pasting, and exiting fullscreen, and optionally use the webcam to flag a phone in frame. None of this auto-fails a student — it's evidence a professor can review, never an automatic grade change.

## Assignments

Professors build assignments in a **Studio** with three kinds of content:

- **Notebook** — a live, code-cell notebook (like a Jupyter notebook), fully round-trippable to the standard `.ipynb` file format.
- **Document** — a Notion-style rich page with slash commands, charts, equations, and interactive elements.
- **Verbal** — an AI-led spoken interview: the student talks to the AI about a topic, and the professor sets the topic, the voice, and how deep the follow-up questions go.

Every assignment gets a rubric (in the style of Gradescope), which can be AI-drafted and then approved by the professor. Grading can lean on AI in a few ways — matching answers by similarity, having an AI model review borderline cases, or a hybrid of both — but a grade only ever becomes final when the professor commits it. The system also learns from every correction a professor makes, so its future suggestions get closer to how that professor actually grades.

There's also a timed, proctored **assessment mode** with a lobby, a work period, and a submission upload step — the actual assignment content is only released once the work period starts, so refreshing the page can't leak it early.

## Live Classroom

This is the real-time, in-class experience. A professor drives a slide deck (PDF, or a PowerPoint that gets converted to PDF) and students follow along on their own devices, seeing the same slide in sync. During class:

- Professors can run **polls** and **AI-generated quiz questions pulled from what's actually being said**, live.
- Students can ask questions and react.
- A **projector view** is a separate, chrome-free window meant for the room's screen — it never shows interaction content or answers, only the slide itself.
- If a student joins late, they can get an **AI catch-up summary** of what's happened so far.
- After class, the professor gets a **session report** (who attended, how engaged they were, an AI narrative summary) and each student gets a **personal study pack** (a summary, how they personally did, flashcards, and a short practice quiz) — with no other student's information in it.
- Before class, a professor can turn on a short **AI-narrated audio preview** of the lecture for students to listen to ahead of time.

## Roadmap and Skills

The **Roadmap** is a visual map of a course — a flowchart of modules and materials — that shows a student where they are and what's next. It is not something a professor manually fills in: a material's status ("covered," "not started," etc.) comes from what's actually happened in the class.

Small AI-generated comprehension questions are attached to each item on the roadmap; a student who says they've gone through it gets asked one to confirm understanding, and the questions are generated the first time a student actually gets there, not in advance.

**Skills** (formerly called "topics") are the individual concepts a course teaches, arranged in a two-level map. Every source of information about what a student knows — quiz answers, live-class questions, uploaded materials — feeds one shared picture per skill, and every student gets a mastery score that updates as they do work, sorted into three bands: Weak, Shaky, Strong. This lets a student (or a professor, at the class level) see exactly which specific ideas need more work — not just "your grade is a B."

## Athena — the AI assistant

Athena is Scholera's single AI identity, but it shows up differently depending on who you are and what screen you're on: a chat console for professors, a small assistant docked into whatever you're building, and a study-focused tutor for students. Full detail in [ATHENA.md](./ATHENA.md). The short version: **Athena can propose things, but a human always has to approve them before anything actually changes.**

## Admin and the institution

Institution admins manage departments, degree programs, courses, and people. They can bulk-import a whole roster by pasting names and emails, review and approve requests to add a TA to a course, and control school-wide settings — including, at the institution level, which AI features are turned on at all. Above that sits a platform-wide switch that Scholera's own staff control, so a feature can be turned off for one school, or for everyone, independent of anything a professor or admin does.

The institution can also decide which product tiers/features it has actually purchased ("entitlements") — a school that hasn't paid for a capability won't see it advertised anywhere in the product, even in captions or hints.

## Course social features

- **Intel** — a crowd-sourced page of reviews, tips, Q&A, and resources about a course, written by students who've taken it and readable by anyone currently enrolled.
- **Discussions and DMs** — course-scoped group channels and private one-on-one messages, using the same underlying chat system.
- **Projects** — team workspaces for group work: phases, shared documents, a team chat channel professors deliberately cannot see (so students have a private space), and meetings.
- **Challenges, badges, and certificates** — professor-defined milestones; certificates can be shared publicly via a link.
- **Calendar and office hours** — a shared calendar and a booking system for office hours.

## Notifications and to-dos

Every meaningful thing that happens in the product (a grade posted, an announcement, a DM) writes to one shared internal log. That log feeds two different-looking things at once: the notification bell, and the "what's due / what's actionable" list on the dashboard — so a student sees the same information in two places without the system doing the work twice. Scheduled sweeps handle things like digest emails and reminders that need to fire without anyone clicking a button.

## Where the AI can be switched off

There's a three-level kill switch for AI features: Scholera can turn a capability off platform-wide, an institution admin can turn it off for their whole school, and — in some cases — a professor's course-level settings decide whether students can reach it at all. Higher levels always win: an institution can't turn on something Scholera has disabled globally.
